# Архитектура и детали реализации

## Поток данных

```text
C/C++ sources
    -> clang-19 (-fprofile-instr-generate -fcoverage-mapping
                 -fsanitize-coverage=bb,no-prune,inline-bool-flag,pc-table)
    -> instrumented executable
        -> *.profraw -> llvm-profdata -> llvm-cov -> coverage.info
        -> bb-<pid>.jsonl -> bb_merge.py -> bb_coverage.json
    -> system genhtml / patched genhtml -> HTML
                                      -> CFG + source-line annotations
```

### Runtime

`runtime/bb_runtime.c` определяет `__sanitizer_cov_bool_flag_init` и
`__sanitizer_cov_pcs_init`. Его компилируют без `-fsanitize-coverage`.
Флаг `hit` фиксирует выполнение блока хотя бы один раз. Runtime сохраняет
пары `(module, pc_offset)` и порядковый номер `slot` таблицы PC; относительный
адрес позволяет пережить ASLR при одинаковом бинарнике. Вывод одного запуска —
`bb-<pid>.jsonl`.

### Объединение

`tools/bb_merge.py` берет логическое ИЛИ `hit` для одинакового `(module, pc)`
из всех запусков и сопоставляет адреса с файлами через `llvm-symbolizer`.
Только блоки, относящиеся к файлам в `coverage.info`, включаются в метрики
по файлам, каталогам и проекту. Полное число инструментированных PC,
неустановленные файлы и PC вне LCOV также сохраняются в `instrumentation`,
`unresolved` и `outside_lcov` — они не пропадают из общего аудита.
`tools/verify_instrumentation.py` проверяет полноту классификации PC.

### Модификация genhtml

`tools/patch_genhtml.py` сохраняет исходный Perl-код установленного
`genhtml` в `bin/genhtml` и добавляет обработку `--bb-report`.
При наличии аргумента после стандартной генерации запускается
`tools/bb_html.py`. Без аргумента стандартный путь генерации не затрагивается.
`tools/compare_compat.py` сверяет строки таблиц покрытия в оригинальном и
совместимом HTML. Он допускает перестановку строк с одинаковыми счетчиками
и различия в служебном `Test Date`, но не изменение числовых значений.

### Строки исходника и CFG

Точки BB сопоставляются со строками DWARF. Отображаемая метка не доказывает,
что блок начинается или заканчивается на этой строке. Блоки без известной
строки показаны в отдельном перечне с PC и статусом.
`tools/audit_locations.py` сравнивает статистику исходных файлов и HTML.

`tools/bb_cfg.py` извлекает переходы из инструкций-терминаторов LLVM IR
(`br`, `switch`, `invoke`, `ret` и др.), а не из произвольных упоминаний
`label` (например, в `phi`). `tools/cfg_graph.py` создает SVG/HTML-графы.
`ENTRY`, `EXIT`, `STOP / EXCEPTION` обозначают структурные точки CFG.
Пунктиром выделяются обратные ребра. Подписи `true`, `false`, `case`,
`default` означают исходы условий, но данные покрытия не доказывают
фактическое выполнение конкретного ребра. Если связь IR-узла с runtime PC
не подтверждена, показывается серый статус `unverified`.

### Вычисление покрытия

Для файла с `N` инструментированными блоками и `H` различными блоками,
выполненными хотя бы в одном запуске: `BB Coverage = H / N * 100%`.
При объединении тестов каждая пара `(module, pc_offset)` учитывается один раз.

## Формат данных

`bb_coverage.json` содержит `schema_version`, `runs`, `summary`, `files`,
`instrumentation`, `unresolved`, `outside_lcov` и (после `bb_cfg.py`) `cfg`.
Для каждого блока фиксируются `id`, `line`, `hit` и, если доступны,
`function` и `slot`. `line=0` означает отсутствие номера строки при известном файле.

## Ограничения эксперимента

- Данные разных сборок несовместимы, так как PC и инструментированные блоки могут меняться
- Флаги `-O0 -g` выбраны для воспроизводимого сопоставления; при оптимизации исходные строки могут соответствовать машинному коду еще менее однозначно
- Примерный сценарий использует один исполняемый файл и тесты без конкурирующих потоков
- Не все PC имеют номер DWARF-строки; в cJSON это 695/1324, в inih 77/128 в проверенном эксперименте
- `--rc check_data_consistency=0` используется для обхода несогласованности экспортированных LLVM записей LCOV по строкам и ветвлениям. При его применении одна из диагностических проверок отключена
- Данные покрытия не подтверждают корректность результата программы и не гарантируют отсутствие ошибок
